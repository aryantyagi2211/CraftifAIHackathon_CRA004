# helmet-guard: helmet compliance pipeline built with CraftifAI PipeGen

Track A (PipeGen) entry for the CraftifAI Physical AI Hackathon.

## Problem
Helmet violations by two-wheeler riders are hard to monitor by hand. This pipeline takes traffic video, detects Helmet / No helmet, tracks each detection with an ID, and writes a JSON event log plus an annotated video.

## PipeGen flow (all five stages)
Requirement -> Pipeline IR -> Model -> Compiler -> Run.
- Input: video file (1920x1080, 340 frames)
- Tasks: detection, helmet classification, tracking (NvMultiObjectTracker, IoU-based)
- Model: YOLOv8n fine-tuned on a Roboflow Universe helmet dataset (by raji, CC BY 4.0, classes Helmet / LP / No helmet), 15 epochs, mAP50 about 0.66 on a 10% validation split
- Precision: FP16 TensorRT engine (helmet_v2.fp16.plan), used by both inference nodes
- Outputs: output/metadata.json (per-frame objects with tracker id, label, confidence, bbox) and output/output.mp4

## Honest limitations
- The model has no rider class. Helmet and No helmet are separate detections, and the No helmet box often covers the whole rider, so one helmeted rider can get both labels.
- Counts in metadata.json are detections across frames, not unique riders.
- Short training (15 epochs), small dataset, partial recall on distant riders.
- Software x264 encoding was the throughput bottleneck (no hardware encoder in WSL2).
- PipeGen's Export Project step failed its portability check (absolute paths in pipeline.sh), so this folder is the raw PipeGen project directory.
- No INT8, no Jetson, no closed-loop or firmware bonus.
